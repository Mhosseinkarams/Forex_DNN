# Labeling Engine

## Purpose
The `LabelEngine` is a critical module in the Forex_DNN quantitative trading framework. It is responsible for generating deterministic, rule-based labels for machine learning datasets. Rather than requiring ML models to learn structural market concepts from scratch, the `LabelEngine` labels historical samples based on pre-defined, high-quality strategy logic generated by `MarketStructureEngine` and `SupplyDemandEngine`.

This decoupled, strategy-driven dataset labeling guarantees that models are trained on clear structural targets, promoting robust and explainable inference.

## Core Features

### 1. Configurable Sliding Window
The engine accepts configurable parameters to define how samples are generated sequentially over the dataset:
- `window_size` (Default: `35` candles): The lookback context window utilized for both feature extraction and labeling rules. Window size experiments can compare values such as `20`, `25`, `35`, `50`, and `75` candles.
- `window_stride` (Default: `1` candle): The stride offset between successive windows.

For each window `[window_start, window_end]`:
- Features are extracted relative to `window_end` (using the entire past window as lookback context).
- Labels are evaluated at `window_end`.

### 2. Deterministic Rule-Based Labeling (`MarketStateLabeler`)
Supports labeling market states into three mutually exclusive regimes without random or manual intervention:
- **TREND**: Triggered by strong EMA separation (`ema_separation_atr >= trend_ema_separation`) and at least one confirmed structure breakout (BOS) in the active window.
- **RANGE**: Triggered by the prolonged absence of BOS combined with either high CHOCH frequency, low/flat EMA separation, or multiple active supply/demand zone rejections.
- **TRANSITION**: Triggered by moderate EMA separation or initial breakouts/reversals (CHOCHs) indicating structural shifts between ranges and trends.

### 3. Handling Unlabeled/Ambiguous Samples
To ensure training set quality, any sample that does not strictly satisfy the deterministic labeling rules or fails to meet the `min_confidence` threshold is **fully removed** from the dataset.
- No arbitrary fallback classes like `UNKNOWN`, `OTHER`, or `UNDEFINED` are created.
- The total count and exact reasons for removals (e.g. `warmup_period`, `ambiguous_or_unclassifiable`, `missing_emas`) are logged and stored in the reproducibility manifest.

## Dataset Validation (`DatasetValidator`)
The `DatasetValidator` executes seven standard quality assurance checks on every generated dataset:
1. **Missing values**: Ensures there are no null/NaN values in any feature or target columns.
2. **Duplicate samples**: Verifies no duplicate rows or timestamps exist in the dataset.
3. **Invalid market structure outputs**: Confirms structural metrics such as BOS/CHOCH counts are non-negative.
4. **Invalid supply/demand outputs**: Checks that zone distances and metrics are positive (or `-1` if no zone is present).
5. **Timestamp consistency**: Verifies that sample timestamps are strictly sorted chronologically (monotonically increasing).
6. **Window consistency**: Assures all start/end indices match the configured `window_size` and sequential stride.
7. **Class distribution**: Summarizes target class ratios and raises warnings for empty classes or extreme class imbalances.

---

## Labeled Dataset Manifest (`.manifest.json`)
A dataset manifest is automatically saved alongside every output CSV to ensure absolute traceability and reproducibility. It records:
- Sliding window configuration (`window_size`, `window_stride`).
- Model and engine versions (`label_version`, `market_structure_engine_version`, etc.).
- Feature registry schema hash (`feature_registry_version`).
- Symbol and timeframe data.
- Date ranges.
- Count of total generated windows vs. successfully retained samples.
- Breakdown of removed samples categorized by reason.
- Final target class distribution.

## Code Example

### Python API Usage
```python
import pandas as pd
from ML.label_engine import LabelEngine
from ML.market_state_labeler import MarketStateLabeler
from ML.dataset_validator import DatasetValidator

# Load historical candles
df = pd.read_csv("output/eurusd_m5.csv")

# 1. Initialize Labeler & Engine
labeler = MarketStateLabeler(min_confidence=0.4)
engine = LabelEngine(window_size=35, window_stride=1)

# 2. Run Sliding Window Generation
dataset_df = engine.generate(
    df=df,
    symbol="EURUSD",
    timeframe="M5",
    labeler=labeler,
    output_csv_path="output/market_state_dataset.csv"
)

# 3. Validate Output Dataset
validator = DatasetValidator(expected_window_size=35)
report = validator.validate(dataset_df)
print(f"Validation Valid: {report['is_valid']}")
```

### CLI Command Usage
To generate datasets and manifests directly from the terminal:
```bash
# Generate using default parameters (Fallback to high-quality synthetic data if no input is provided)
PYTHONPATH=. python scripts/generate_dataset.py --output output/market_state_dataset.csv

# Run with customized window configurations
PYTHONPATH=. python scripts/generate_dataset.py \
  --input output/eurusd_m5.csv \
  --output output/market_state_dataset_w50.csv \
  --window_size 50 \
  --window_stride 1 \
  --min_confidence 0.4
```
