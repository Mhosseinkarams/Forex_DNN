# Training Guide: Machine Learning Workflow

This document describes the complete machine learning pipeline for the Forex Trading Framework, from data generation to live inference.

## Current Project Status

The framework supports Deep Learning (DNN/LSTM) and Reinforcement Learning (RL) approaches. It provides a structured way to extract features from technical indicators and labels from trade outcomes.

## Feature Generation

Features are generated by the `IndicatorEngine`. For every bar, the framework calculates:
- **Trend Features**: EMA slopes (50, 600, 800).
- **Momentum Features**: EMA distances, crossovers.
- **Candle Features**: Body-to-wick ratios, size relative to average.
- **Volatility Features**: ATR-normalized distances.

These features are automatically captured by `MMStrategy` and logged in the `TradingJournal` for every signal.

## Dataset Creation

To create a training dataset:
1.  **Run Backtests**: Run extensive backtests over multiple years of data.
2.  **Collect Signals**: The framework logs every signal (whether executed or blocked) to `Journals/backtest/events/*_signals.csv`.
3.  **Collect Outcomes**: Once trades close, the `PositionLifecycle` summary contains the `realized_profit` and `result` (WIN/LOSS).

### Labeling
Signals are labeled by joining the Signal ID with the final Outcome:
- **Binary Classification**: WIN (1) vs LOSS (0).
- **Multi-Class Classification**: WIN, LOSS, BREAKEVEN.
- **Regression**: Predict the actual `r_multiple` or `profit_dollars`.

## Journal Usage for ML

The `TradingJournal` is the primary source for ML data.
- Use `signals.csv` for features at the time of entry.
- Use `positions.csv` (Layer 2 summaries) for targets/labels.

## Training Pipeline

The training code is located in the `DNN/` and `RL_Approach/` directories.

### Deep Learning (DNN/LSTM)
1.  **Preprocess**: Use `Collecting_Data/preproc_multi_inout.py` to normalize data and create sequences.
2.  **Train**: Run `DNN/multi_inout/classifier_multi.py`.
3.  **Evaluate**: Check accuracy, precision, recall, and F1-score. Use `model.png` to visualize the architecture.

### Reinforcement Learning (PPO)
1.  **Environment**: `RL_Approach/trading_env.py` provides an OpenAI Gym environment.
2.  **Agent**: `RL_Approach/ppo_trading.py` uses Stable Baselines3 to train a PPO agent.
3.  **Rewards**: Calculated based on realized PnL and drawdown avoidance.

## Validation & Testing

- **Chronological Split**: Never use random shuffling. Always split data chronologically (e.g., Train: 2018-2021, Val: 2022, Test: 2023).
- **Walk-Forward Optimization**: Use `RL_Approach/walk_forward.py` to perform rolling window validation.

## Model Export & Inference

1.  **Export**: Save models as `.h5` (TensorFlow) or `.zip` (SB3).
2.  **Inference**: In `MMStrategy`, load the model during `__init__`.
3.  **Filter**: Before calling `SendOrder.execute()`, pass the current feature vector through `model.predict()`. If the confidence is low, discard the signal.

## Future Roadmap

- **Feature Store**: Centralized repository for pre-calculated technical features.
- **Auto-Labeling**: Automated script to generate labels from broker history without running full simulations.
- **Online Learning**: Updating models in real-time as new trade outcomes are recorded.

## Example: Creating a Dataset

```python
import pandas as pd

# Load signals and outcomes
signals = pd.read_csv("Journals/backtest/events/mm_EURUSD_o_M5_events.csv")
signals = signals[signals['event_type'] == 'signal']

outcomes = pd.read_csv("Journals/backtest/positions/mm_EURUSD_o_M5_positions.csv")

# Merge on signal_id
df = pd.merge(signals, outcomes, left_on='signal_id', right_on='signal_signal_id')

# Create target
df['target'] = (df['outcome_result'] == 'WIN').astype(int)

# Extract features (prefixed with 'signal_')
features = [col for col in df.columns if col.startswith('signal_indicator_snapshot_')]
X = df[features]
y = df['target']

print(f"Dataset created with {len(df)} samples and {len(features)} features.")
```
